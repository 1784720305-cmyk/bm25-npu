## 两份实现的区别

| 项目 | 固定原版 BM25S | 当前 warp 追加 NPU |
|---|---|---|
| 源码 | 原版提交 03eac5a8fb3aa4958ce37415a4cf2220d35157f7，25 个固定源码文件逐一哈希核对 | 已验收 warp 聚合直接追加版本及原有主机程序 |
| 索引内容 | CSC 稀疏表：词边界 indptr、文章 indices、预计算贡献 data | 词边界/叶目录、文章 ID、TF、doc norm、IDF |
| 建索引 | 预先计算每个词对各命中文章的 BM25 贡献 | 保留公式所需数值，贡献留到每次查询计算 |
| 查询评分 | 读取贡献，按查询词次序累加到整篇库评分数组 | 按叶块计算 FP32 贡献并累加，评分/局部选择融合 |
| 并行 | 原生 Numba 按查询并行；Q8 最多 8 个查询任务，32 个请求线程不等于 32 个有效查询任务 | Q8 的许多叶块任务分给设备执行单元 |
| Top-K | 原生 Numba 遍历全部文章分数并维护 K 元素堆 | 正分 ID 直接追加、精确阈值选择、32 路分层合并 |
| 同分 | 原生接口不保证项目的文章 ID 升序规则 | 分数降序，同分文章 ID 升序 |
| 每次传输 | 只有 CPU 内存访问 | 查询 H2D、结果 D2H，索引常驻设备 |

BM25S 的算法已经针对查询速度做了优化，“原版”不能理解成“朴素且慢”。本对照保留它的贡献预计算和原生 Numba，不改上游源文件，不把公式改成较慢的查询期计算。选择 ATIRE TF 与 Lucene IDF、k1=1.2、b=0.75，与项目数学公式对齐，而非使用可能不同的库默认 BM25 变体。

`original_native` 是未修改的原版 retrieve；`strict_adapter` 是现有包装层调用原版编译评分器，再按项目规则选 K，额外适配和每次线程池开销都计时。它是满足严格规则的独立参考，不称为原版自身，也不声称是最优适配实现。两个接口分别对比 NPU，不混合取最快者。各接口内部逐轮取已声明 1、8、32 线程配置的较快结果，P95 独立取较低者。

## 数据、边界与正确性

默认规模 1024、8192、65536、262144、1048576、4194304、10000000 篇，复用 `warp_append_scales1` 中已验收的相同输入，每档仍 Q8、3 词、K10、A/B 查询和固定生成规则。语料仍为合成数据，非 MT 认可业务数据。扩大文章库，不以扩大查询批量替代。

从 CPU 内存中的原始词 ID 进入 Search，到 CPU 持有 Top-K。包含查询验证、整理、索引检索、计算、选择和必要输出检查；NPU 包含传输/同步。建库、贡献预计算、索引加载/上传、首次 JIT、预热、文件读写和独立正确性核对排除在稳态 Search 外；建库耗时、索引字节另报。

BM25S 调用原版公开 `BM25.index` 和原版 `activate_numba_csc` 建库。使用可重复遍历的语料对象重新生成同一批文章，避免同时持有千万个 Python 文章列表；没有从 NPU 的 TF 数组注入预计算贡献。现有大库格式与旧 BM25S 小库入口不同，新入口不会把文件名换一下就强行套用旧程序。

建库时，全部 A/B 查询的完整分数与现有独立 FP32 参考按原容差比较；严格选出的 ID 与项目期望逐项核对。BM25S 原生贡献算式的 FP32 运算次序与 NPU 可能导致近似同分排名差异：`strict_ids_match_project` 若为 false，保留差异并标记不能认定严格等价获胜，不扩大容差，也不以 NPU 参考输出替代实际 BM25S 结果。

每次原生结果核对所选文章的实际分数、精确 Top-K 分数集合及重复调用一致性，另外记录与 BM25S 自身严格规则的 ID 差异。严格适配结果必须与 BM25S 自身严格规则完全一致。NPU 复用原有完整分数、叶块/各级合并、严格 ID、索引不变及保护区检查。

## 看什么结果

每档末尾 `BM25S comparison decision` 分开给出原生与严格适配的 A/B 六轮中位数、P95、倍率和胜轮。`timing_gate_passed` 只表示六轮全胜且六轮 P95 中位数更低；原生接口即使时间获胜，也不据此宣称满足严格同分规则。只有严格适配且项目 ID 等价，`strict_equivalent_win` 才能为 true。

最后 `BM25S/NPU coverage` 和 `report.json` 汇总全部档位；`summary.csv` 是方便发会的汇总表。`strict_stable_npu_winning_docs` 为当前对照中满足严格等价和稳定领先的规模。退出 0 代表所选档位覆盖完成，不代表 NPU 全部获胜。
