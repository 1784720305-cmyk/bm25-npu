# 原Radix与零分汇总版同期比较

最新结论：本页实验在同输入、同卡的六轮中全部慢于原Radix，暂不采用；原版/零分汇总版六个运行中位数再取中位数为0.4097545ms/0.419935ms。新版Top-K有效采集中位数311.232us，仍是最大一段；不能从段总时间确定内部哪条指令主导。结果及源码保留，不继续重复本页同一实验。下一步见 [候选收集修订路线](Radix候选收集修订路线.md)，当前只有本地模型，不是新设备实现或速度验证。

## 当前已经证明什么

用户在设备2上已完成零分汇总版编译、独立安装、实际接口/依赖核对及23组完整验收。共115次A/B交替实际NPU调用的全部编号、原FP32字节、每次完整排序及A/B独立Python检查均通过。

新版四段也已在原小样本（22条贡献、36组总分、18个最终结果）及262144文章/8查询/K=10（192889条贡献、2097152组总分、80个最终结果）通过完整公式、局部候选、最终排序、首末/重复六数组及CPU交叉核对。大样本贡献最大绝对误差4.7683716e-7，文章总分/Top-K分数9.5367432e-7；全部80个编号及顺序严格一致。

这证明已测试范围内的设备计算正确。大样本本次预热2次、测量3次的诊断中位数0.417896ms，与原版历史0.41ms附近接近，不能据此判断收益或退化。完整查询、BM25S、含传输以及最佳CPU的比较仍未完成。

## 输入、过程、输出

输入仍是原来的performance合成语料计算数组，不重新生成。使用相同设备2、S=32、同一个已编译的四段调用器。原版运行目录为results/radix_sharded_runtime/vendors，新版为results/radix_zero_sharded_runtime/vendors。贡献、累加、最终合并安装及Top-K主机分核源码必须相同，只有局部Top-K设备实现不同。

比较六轮。奇数轮原版先跑，偶数轮新版先跑，双方各先跑三轮。每个版本都由新进程启动，预热5次、正式测量30次，使用原resident计时边界：包含每轮接口准备、四次提交和整链同步，不包含初始化/内存分配、输入整理、传输、文件和结果核对。不是纯内核计时。

每次调用都复用原run_sharded_pipeline.py的实际设备执行和完整验收。父程序再次核对报告参数、调用器/输入/安装来源、计时原始样本、完整局部及最终排序、独立公式以及首末输出。每轮新旧全部六数组必须字节一致，各轮也必须重复一致；失败、中断或期间来源改变则保留部分日志/失败报告，不生成成功汇总，不生成CPU替代输出。

输出目录中report.json保留每轮进程顺序、双方耗时与p95、文件指纹、安装版本和逐轮原版时间/新版时间。summary.json给出各轮中位数及配对比值，原始样本仍在各轮版本目录的npu_timing.json中。比值>1是新版更快，<1是原版更快；配对比值中位数、六个中位数再取中位数不是同一个统计量。不能把每轮p95合并成总体p95。

## 黄区执行

只新增Python对比工具及文档，不改任何已验收的算子、调用器、独立验收器或样本，无需重编译、重装或重复23组验收。同步新代码后执行，设备2须空闲，普通性能对比不包msprof：

```bash
cd /test/w50066029/bm25-npu
python3 verify_package.py
set -o pipefail
python3 standalone/compare_radix_versions.py --input results/normal_256k_q8_batch1 --output results/radix_zero_vs_original_256k_q8_pair1 --device 2 --shards 32 --rounds 6 --warmup 5 --repeats 30 2>&1 | tee results/radix_zero_vs_original_256k_q8_pair1.log
```

代码明确要求原版与零分汇总版各自的运行记录及此前设备验收，不会自动选择其他Top-K。输出目录须为新目录；重复执行同名命令会被拒绝，同名tee还可能覆盖顶层日志，勿重复粘贴已经完成的命令。

验收成功应打印：新旧六数组核对全部通过、原版各轮中位数、新版各轮中位数、逐轮原版时间/新版时间、新版更快轮数及报告路径。黄区文件留在黄区，只分享允许的终端摘要。

## 如何决定下一步

若新版在相同条件下有可重复的整链收益，再做新版设备分段诊断，确认Top-K是否改善，并检查原64K/单查询、256K/单查询及非零较多输入是否退化，之后与较快CPU作同期比较。不要仅因删除了一批atomic更新就切换默认。

若六轮仍基本持平或新版更慢，就记录该项优化没有达到目标，不继续扩大同类六轮测试来寻找好看的数字；根据新旧设备诊断决定转查候选收集或累加。当前完整分数读写、零分扫描和协作候选收集仍保留。若以后压缩无贡献文章或改变输入格式，CPU/NPU须使用相同规则，并单列整理和传输成本。

这次工具只比较两个NPU版本，不重新执行CPU，不代表最终任务达标。单个最低点、接近1的比值或共享服务器的CPU波动不能用来证明稳定加速。
