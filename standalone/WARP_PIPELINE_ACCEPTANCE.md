# NPU warp分配与候选收集优化验收

日期：2026年10月27日。状态：已审阅源码、通过本地模型与验收逻辑检查，尚无本候选CANN编译、A5正确性或性能结果。当前已验收基线仍为Sparse Pack，千万篇A/B完整Search为2.444224/2.419552ms；这些历史时间不能充当本候选的新成绩。

## 改动内容与技术判断

这次组合了两个NPU内部改动，不是评分与传输重叠的异步流水：

1. Pack阶段：256线程组成8个warp。每warp通过shuffle计算局部前缀，由最后一个lane为该warp一次性原子分配连续输出段。去掉正常评分位图路径中的全块PrefixPair；保留Pack结束的全块屏障，待所有warp分配与写入完成后统一决定容量及回退模式。
2. Collect阶段：严格优于阈值的候选也用warp前缀与原子游标分配槽位，去掉该处全块PrefixPair。阈值分数只需补1名时，各线程将本地最小同分文章ID通过atomicMin归入固定槽位，直接进入最终32槽精确排序；需要补多名时仍使用现有有序归并。

`remaining == 1`不要求阈值分数全局唯一；可以有多个同分文章，但只需其中ID最小的一名。这次验收衡量两个改动的组合净收益，不单独归因每一项。

各warp取得段的先后顺序可变化，所以中间压缩数组不再按全块线程号固定排列。每线程自己所属段仍按真实文章ID升序，owner元数据随段更新；整数阈值统计不依赖输入排列，最终按分数降序、真实全局ID升序精确排序。正确性不能以压缩位置作为同分裁决依据。

评分FP32公式、查询词顺序、Sparse Pack的置位发射、精确阈值、稠密/少量回退、全局ID、分级合并、8192篇叶宽、256线程、UB声明、ABI和主机Search保持不变。CPU实现、二进制、线程配置和计时边界保持原先对手。可能的收益是减少全块前缀和同步及单名补齐归并；新增原子争用、shuffle、寄存器或编译调度成本可能抵消收益，必须实测。

## 审阅与本地检查

- 核对Pack游标每个正常任务清零、Collect游标与错误计数每次Pack初始化；阈值控制和全局ID基址不与新游标重叠。
- 原子分配只写完整落入容量的段；超过1024正分时统一回退，不能截断后返回部分Top-K。
- 调整前后的生成源码可按明确替换逆向还原，其他生成文件逐字一致。导入新驱动不能修改已验收Sparse Pack模块的全局状态。
- 980组warp不同到达顺序/容量模型，包含204组阈值只补1名、100组需补多名；另72组K1/10/32、0/1/K边界及1023/1024/1025容量边界模型通过。
- 检查直接选择Sparse Pack逐轮candidate，并绑定实际运行别名到已验收的安装目录，拒绝指向旧位图版；验证七档即使性能落后也继续、其余档位复用首档候选。
- 原子及shuffle声明搜索覆盖同一实际SIMT头文件目录；无法通过文本找到的名字记入报告，不据此认定API不支持。实际UB重载、内建函数、类型、编译及内存可见性仍由黄区CANN与设备执行确认。

以上均为本地模型或静态/调度检查，不是CANN或设备证据。未更改已验收Sparse Pack、CPU、主机和合并实现。

其余档位使用同一候选安装与受影响边界检查的SHA256证据，不重复编译旧组件。所有档位均重新测Sparse Pack基线、新候选和CPU，千万篇也须新测。完整Search仍从原始CPU词ID开始，到CPU取得Top-K结束，包含输入整理、H2D、全部计算与合并、同步及D2H；初始化和诊断不计入普通性能。

## 验收判据与输出

每档末尾为`NPU warp流水六轮判定`，总末尾为`NPU warp流水全规模覆盖`。

- `versus_verified_npu`：与本轮同期已验收Sparse Pack直接比较，不能用旧位图版或更早NPU计算新收益。
- `versus_all_declared_cpu_configs`：每轮取该档已声明CPU配置的较快者，A/B均6/6中位耗时更低且六轮P95中位数更低，才算该档稳定超过CPU。
- `retain_candidate`：延续预声明候选门槛，A/B均6/6快于Sparse Pack，耗时下降至少5%，P95改善，并通过CPU稳定门槛。5%是优化保留门槛，不是MT对NPU/CPU的业务要求。
- `stable_cpu_winning_docs`和`retained_candidate_docs`分别列出实际获胜规模。`correct_but_not_retained`不表示正确性失败，需分别看增量收益及CPU门槛。
