当前整改版的复现命令和必要环境变量见 [A5 两阶段验收](docs/A5_ACCEPTANCE.md)。本轮千万篇六轮中位数汇总：NPU A/B 为 **2.004 / 1.979 ms**，每轮均快于同轮两种 32 线程 C++ CPU 实现中的较快者，P95 也更低。本次 CPU 波动较大，本会话约 6.05 / 6.97 倍的倍率不表示结构整改带来了对应的 NPU 优化，也不替代历史会话结果。后续“已有实测”保留整改前的记录。

CPU 相对旧版的速度保持尚未由上述门槛证明。[CPU 回归核查](docs/CPU_REGRESSION.md)已收到同机绑定后的三组对照：旧版 A/B 为 5.473/5.552 ms，新版 5.753/5.785 ms，新源码恢复旧参数后为 5.395/5.390 ms。此前数倍差距未复现；同一新版两次试验自身相差约 13%，且存在较高系统负载背景，不能把汇总约 4%～5% 的差异认定为编译参数的固定开销。CPU 检索实现、算子及当前编译策略保持不变，剩余差异待空闲窗口复核。

2026-11-05 的 [原版 BM25S 性能回归](docs/BM25S_PERFORMANCE.md)已完成：千万篇/Q8/K10 的 NPU A/B 为 **1.993/1.979 ms**，较历史分别变化 **-0.51%/+0.04%**，满足“与此前接近”的目标。原版 BM25S 同轮较快配置约 31.383/31.446 ms，NPU 延迟领先约 15.75/15.89 倍，A/B 均六轮全胜；倍率下降来自本会话 CPU 更快，NPU 仍约 2 ms。[回传证据](evidence/bm25s_regression_a5_20261105.json)已复核。[SciFact 真实数据](docs/SCIFACT_REAL_DATA.md)的 A5 测量也已完成：300 条查询的质量指标与原版 BM25S 三种线程配置一致；固定 Q8 样本 A 比 CPU 慢 **3.37%**、B 快 **5.37%**，小库不宣称整体领先。C++ 配对保留作辅助诊断；稳定的实测差距如实记录，不笼统归因于系统负载。

## 使用

1. 运行 `python3 verify_package.py`。
2. 按[构建与验收](docs/BUILD_AND_TEST.md)复用最终安装或从实际CANN模板构建。
3. 用large_corpus准备数据，benchmark_final做六轮对照。
4. 架构、清理范围与边界见[交付说明](docs/FINAL_DELIVERY.md)。
